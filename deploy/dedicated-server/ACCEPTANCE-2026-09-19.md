# Issue 101 腾讯云公网验收记录

## 环境

- Linux x86_64 Dedicated Server，`systemd` 管理，非 root `fps` 用户运行。
- Unity Transport 监听 `0.0.0.0:17777/udp`；正式配置的空闲回收时间为 120 秒。
- 应用版本 `0.1.0`、协议版本 `1`、内容版本 `citynew-v1`。
- 两个独立的 macOS 客户端使用短期账号票据，无界面、无声音运行。
- 真实公网路径为客户端移动热点到腾讯云实例；服务端抓包确认客户端 UDP 到达。

## 结果

2026-09-19 的第一次完整战斗尝试中，客户端 A 在射击采样阶段被敌人击倒，自动验收失败。网络连接已经建立，客户端 B 收到权威 Tick 和状态；此失败不能归因于防火墙或认证。重新启动全新战局、重新签发票据后，运行 ID `issue101-remote-20260919T052426Z` 的双客户端流程通过：

| --- | --- | --- |

客户端 A 时间轴记录：`room.join`、射击反馈 `20` 次（其中命中 `5` 次）、清除 `6` 名敌人、终端任务、撤离与胜利结算均通过。客户端 B 最终记录约 `155 ms` RTT、`1222` 次预测采样、`31` 次位置校正。该战局服务端诊断记录接收 `759887` 字节、发送 `4340282` 字节、拒绝连接 `0` 次，`lastRuntimeException` 为空。

验收脚本在远程真实战斗中存在一次被敌人击倒的偶发失败，后续应单独跟踪自动驾驶与战斗时序的稳定性。一次全流程通过证明公网链路和功能可用，但不等于长期稳定性已经量化。

测试结束后已删除两端临时连接票据，并恢复正式 `120` 秒空闲回收配置。认证密钥从服务器权限为 `0600` 的环境文件注入，未出现在本记录或仓库中。
