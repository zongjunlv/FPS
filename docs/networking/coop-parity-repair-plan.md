# 联机 PvE 综合修复方案

## 1. 目标、范围与结论边界

目标：在 CityNew 中实现与单机一致的完整双人 PvE 玩法和表现，由服务器统一结算，客户端持续交换输入与状态，直至任务完成、撤离和结算。

本方案合并本轮和前轮发现的问题：敌人滑移/原地踏步、后续生成模型消失、血条跳跃、可见模型与命中疑似错位、异常受伤、立体掉落缺失、升级卡片不一致、状态更新长时间停顿，以及退出后再次进入对局的生命周期错误。

账号、登录、房间和模式入口已通过的功能不重做；鼠标恢复、房间清理、ESC 退出作为回归项。战斗继续使用 UDP，不改成 TCP，不替换 CityNew，不引入新的测试占位玩法。

### 已确认与待验证

| 问题 | 已有依据 | 当前不能断言的部分 |
| --- | --- | --- |
| 滑移、原地踏步 | 联机禁用了 EnemyVisualAnimator，却未接入有效的行为/速度动画驱动 | 不能保证所有滑移都只由动画造成，仍需排除位置错位 |
| 后续模型消失、跟随玩家、打模型不掉血 | 完整敌人 Prefab 的延迟 Awake 可能新增本地 AI；模型加载复用缺少代次校验 | 此次现场尚未完整记录子模型 X/Z 与激活后组件，具体因果链未证实 |
| 血条脱离模型、屏幕跳跃 | 血条使用统一固定高度，缺少模型就绪及有效投影保护 | 不能把全部跳跃都归为血条代码，需同时检查复制根与模型 |
| 远距离视觉与命中范围不符 | 现有联机 LOD 按距离把正式模型缩成 0.75/0.55 倍，服务端命中范围不随之变化 | 是已确认的不一致机制，但不是所有未命中的唯一解释 |
| 道具没有立体包体 | 联机只构造二维 SpriteRenderer 图标 | 不是服务器完全没有生成掉落数据 |
| 升级界面不同 | 联机使用 IMGUI 文字按钮，没有复用单机卡片视图 | 不需要把升级结算移到客户端 |
| 长时间停顿 | 一场对局有约 29.9 秒状态应用空档；另两场状态持续更新但大量 Miss | 空档尚未定位到网络、服务器或客户端主线程，不能统称 UDP 延迟 |
| 再次进入失败 | 两次出现 spawn barrier 必须在 startup 前配置的错误；另有一次连接超时 | 初始化错误与公网连接超时不是同一故障 |

修复不以“扩大碰撞体”“恢复全部 AI 脚本”“调高 Tick 率”或“把输入未来窗口调大”作为替代方案。

## 2. 必须保持的职责边界

- 服务器：敌人 AI/导航、玩家权威移动、命中与伤害、生命护甲、掉落归属与拾取、库存、升级效果、波次与任务进度。
- 本地玩家客户端：采样并发送意图，预测自己的移动，收到确认后校正；可以立即播放枪口/后坐力等非结算反馈。
- 敌人和队友客户端表现：消费带时间戳的权威状态，插值位置、播放动画、显示血条；不运行另一份追击/伤害逻辑。
- 共用 UI：保留单机的美术和交互，但通过联网适配层读取服务器状态、提交意图，不调用单机本地结算。

纯表现 Prefab、权威命中配置和单机玩法 Prefab 分开管理，通过稳定的模型/敌人类型 ID 对应。不要为修联机而破坏单机资源。

## 3. 按依赖拆分的修复项

下面编号是方案内编号，不是已经创建的 GitHub Issue。每项先建立能复现该问题的失败测试，再实施并验证；不把多个未验证改动一次性堆入项目。

### 修复项 1：建立同一场对局的可判定诊断与回归基线

**要解决：** 不再混合不同对局的序号、误用表现根坐标证明模型可见，或将所有停顿归因网络。

**措施：**

1. 每条关键记录携带 MatchId、运行/连接代次、构建/协议版本、PlayerId、命令序号；敌人记录 TargetId、SpawnGeneration 和该实体数据真正的快照 Tick。不能用后来更新的世界 Tick 冒充敌人位置的生成时间。
2. 分别记录输入采样/提交/服务器接受或拒绝，传输接收/主线程状态应用，以及服务端 Tick 耗时。运行时不能直接取得 socket 级数据时，明确写出观测边界，必要时只对真实对局进行两端短时抓包。
3. 模型记录主体网格的就绪、激活、可见投影、局部 XYZ、世界位置和启用组件；血条记录锚点与相机；射击记录视线、枪口射线、回溯时间、目标代次和判定原因。
4. 记录客户端帧耗时、GC/暂停/失焦，以及服务器 Tick 耗时和补步积压。日志采用限频结构化记录或有界缓冲，不逐帧打印大量完整调用栈；禁止记录密码、密钥或认证票据。同机阶段用单调时间计算耗时，跨机用序号/Tick 关联，不能未经时钟偏差校准直接相减 UTC。
5. 以正式资源复现“初始敌人击杀→补生成→池复用”，保存失败断言和画面。最小自动化复现用于定位，最终仍验证真实客户端，不用探针通畅替代游戏通畅。

**验收：** 可以明确区分“服务器位置错误、显示根错误、模型子节点错误、射线错误、包未到达、包到达但未应用”；每个结论对应同一实体、同一代次和同一场对局。

### 修复项 2：修正启动、退出与再次进入的完整生命周期（P0）

**要解决：** spawn barrier 初始化顺序错误、旧任务污染新对局、失败返回后鼠标不可用，以及幽灵房间回归。

**措施：**

- 显式状态顺序：准备配置与资源 → 配置玩家生成屏障 → 启动网络 → 完整初始状态就绪 → 开放操作。每次连接拥有独立代次。
- 退出/超时先取消旧加载与连接任务、清理未使用票据，解绑事件并等待 Shutdown 完成、旧 NetworkManager 不再监听，再配置下一场的生成屏障和启动；旧回调不得改变新房间或新对局。不能删除“正在监听时禁止重新配置”的保护来隐藏错误。
- 所有失败出口统一恢复大厅 UI、可见且未锁定的鼠标、输入焦点；清理暂停/经济弹窗输入锁和恢复遮罩。
- 明确区分“初始化失败”和“网络超时”，给出正确提示。
- 房主离开、战斗启动失败和租约到期按现有房间规则清理；校验持久化房间列表不展示无有效房主的孤儿记录。此前已修复项以回归验证为主，不擅自删除正常房间。

**验收：** 连续至少十轮进入→退出/取消/超时→重入无初始化错误；模拟连接失败后仍能鼠标操作并再次建房；ESC 退出、失败、正常结算均恢复正确页面；不存在可加入但永远不能开始的孤儿房间。

### 修复项 3：隔离客户端敌人模型，修正异步加载和池复用（P0）

**要解决：** 模型消失、模型跟着本地玩家移动、潜在的本地重复 AI/伤害。

**措施：**

- 为各正式模型生成/制作纯表现 Prefab，保留网格、骨骼、材质、Animator、明确允许的视觉组件与锚点。加载前就不含 EnemyController、感知、导航、战斗、Health 结算或 NavMesh 构建逻辑。
- 不沿用“实例化完整玩法 Prefab 后禁用全部 MonoBehaviour”的安全假设；禁用组件不代表 Awake 不会产生副作用。
- 以“战局/连接代次 + TargetId + SpawnGeneration + 模型地址/加载令牌”核验异步结果。旧请求完成后只能释放，不能挂到新敌人。
- 明确分离权威显示根和视觉子节点。根只由网络表现器控制；动画/浮动只作用视觉子节点，并以资源基准姿态为界。
- 出生、死亡、隐藏、复用、换模型时重置姿态、动画、血条和加载状态；Addressables 实例与资源句柄配对释放。
- 加载失败给出可追踪错误并采取明确恢复/退出策略，不能显示无限期孤立血条假装成功。
- 客户端生命护甲只消费服务器确认状态，记录伤害来源以排除残留本地 ApplyDamage 路径。

**验收：** 所有正式敌人类型覆盖首次激活、补生成和复用；人为延迟模型加载并先回收/换代，旧模型不会闪现，资源释放回到基线；主体网格实际可见；视觉子节点没有非设计偏移；客户端没有敌人 AI/导航/伤害脚本运行；停止本地玩家输入也不会让敌人显示冻结或随玩家一起漂移；无服务器伤害确认时不出现本地扣血。销毁客户端模型不改变服务器生命、掉落或任务状态。

### 修复项 4：持续输入、服务端输入缓冲和带 Tick 快照表现（P0）

**要解决：** 下行短时停更触发停发、网络抖动引起世界走停，以及约 30 秒空档。

**现状边界：** 项目已有本地预测/校正、其他玩家插值和命中历史，不是从零实现。当前发送额度仍依赖最近复制的 ServerTick；默认未来窗口为 1，正式对局实际参数须读取运行规则。敌人仍主要追赶最新目标，而非按快照时间线显示。

**措施：**

1. 独立输入采样、提交节奏和命令序号；不再用“必须先收到下一份快照”作为正常发送的直接开关。结合单调时间、RTT/抖动和最新确认估计服务器时间，并协调服务端命令窗口。
2. 本地预测保留有界未确认队列；按服务端已处理序号移除和重放。严重失联时限时预测并明确断线/恢复，不无限积压，也不恢复后一次性倾倒旧命令。
3. 服务端按玩家维护短输入缓冲，记录迟到/缺失/积压。短时沿用移动状态须有严格时限；跳跃、开火、拾取等动作按唯一序号去重，不能因缺包自行重复。过期和超前输入继续受验证，不取消防作弊约束。
4. 区分 UDP 传输与消息可靠性：高频状态/移动是否被可靠有序队列阻塞应实测。当前移动、跳跃、开火共用可靠有序路径和领域序列；若分通道，须一起设计确认序列与跨通道顺序，防止后到的开火被新移动序号越过。移动使用最新状态及必要冗余，离散动作使用确认/去重策略；不能把全部 RPC 直接改成不可靠。
5. 给敌人/掉落状态补齐真正的生成 Tick、序号/Revision，或纳入原子快照包络；敌人与队友使用统一的快照展示时间线，按到达抖动设置有界缓冲。生成、死亡、瞬移、代次变化不跨边界插值；短时缺包可极短有限外推，长期缺包停止并告警，不能凭空继续 AI。
6. 对长空档先区分：服务端是否仍按时推进、客户端是否收到传输消息、主线程是否及时处理。按实际最早失效环节修复主线程阻塞、队列拥塞、背景运行策略或网络断流，不能仅靠加大插值掩盖。

**验收：** 在可控延迟、抖动和少量丢包下，采样、提交、接受、状态应用持续推进，包括玩家静止时的健康检查；短暂下行停更不直接锁死上行；队列有上限且恢复后收敛；松键与离散动作不被重复结算；长期失联清晰退出或恢复。记录 RTT、快照年龄、应用间隔、预测误差与服务端 Tick 耗时，比较同条件修复前后结果。真实公网完整对局不得出现无法解释的长空档。

### 修复项 5：对齐玩家所见、权威命中体与伤害反馈（P0）

**要解决：** 看到敌人却打不中、模型与真实位置不同步、延迟下命中感觉异常。

**措施：**

- 每种模型配置同一套坐标约定：权威根、视觉基准、身体/头部命中区域、显示锚点。根据正式网格校准，不统一放大球形判定区。
- 移除以缩小正式模型实现距离 LOD 的做法。LOD 改为网格细节、材质或动画更新频率优化，保持世界尺寸和命中体一致。
- 检查准星/相机视线、ADS/后坐力、枪口起点和服务端采用的方向，明确“视线选点、枪口到目标是否受阻”的射击规则。近处掩体阻挡必须有合理且一致的反馈。
  - 当前显式射线保护仅做方向合理性校验（sanity validation）：有限、单位方向保留 45° 粗上限；实际最近命中候选在同一展示历史与出生代次下，以未膨胀命中体距离校验横向误差。角度预算为独立的权威武器最大散布（步枪 5.2°、手枪 5.6°）加固定 `MaxCameraRecoilDeviationDegrees = 11°`，后者覆盖正式 PlayerGameplayRig 的垂直 10°／水平 3° 后坐力组合。另允许受枪口距玩家 ≤2.5m、实际相机高度 1.05–1.65m 限制的近距视差；无伤害候选保留粗校验供空枪使用。不新增线协议字段，不将相机后坐力混入移动／基础瞄准输入。服务端未重演后坐力与随机散布，预算内客户端偏差仍可能被接受，因此不是完整反作弊。
- 射击请求关联命令序号、经校验的时间基准和目标出生代次。命中历史按玩家看到的服务器展示时间取样，考虑插值延后，且受回溯上限和身份/位置验证约束；不简单回退固定 RTT，更不重算整场 AI 历史。
- 血量、死亡和击杀奖励只由服务端确认。立即播放的枪口和后坐力是本地表现，命中反馈不能未经确认伪造。
- 每次射击可区分命中、掩体阻挡、真正未命中、射速拒绝、过期或代次不符；拒绝也返回明确的序号和原因，并与弹药显示对账。无反馈与明确 Miss 分开统计。

空间校准在纯表现模型隔离后优先进行；回溯时间与延迟场景在修复项 4 完成后再联调验证，避免先用网络平滑掩盖坐标错误。

**验收：** 正式各类模型的身体、有效弱点、边缘与掩体射击均有对照；移动目标在受控延迟下仍有合理命中；两个客户端对同一敌人的生命与死亡结果一致；旧出生代次的射击不命中新复用敌人。不能仅以“出现扣血”判定通过。

### 修复项 6：恢复完整动画，并让血条与模型同步（P1）

**要解决：** 滑移、原地踏步、攻击动作缺失、血条过高或飞出画面。

**措施：**

- 建立只读网络动画驱动，输入服务器行为、展示时间线速度和攻击/死亡事件；不读取被禁用 NavMeshAgent 的零速度，也不重新启用单机 AI。
- 根据现有资源匹配待机、移动、攻击、受击和死亡；资源确实缺少的动作明确列出，不宣称已有。Root Motion 不驱动权威显示根；攻击消费服务端攻击事件并按代次/事件序号去重，不因每帧处于 Attack 状态就重播。Animation Event 不结算伤害，瞬移/复用也不能被当作高速行走。
- 无人机浮动限制在设计范围，并使可见主体与命中配置协调；不通过随意抬高模型掩盖地形或位置错误。
- 各模型使用独立 StatusAnchor；没有时用主体网格的稳定基准计算，不能采用第一个 Renderer 或统一 2.15 米偏移。
- 模型未就绪、死亡/回收、投影在相机后、近裁剪面之外或屏幕外时正确隐藏/裁剪；遮挡策略统一。每个敌人只保留一组血条和状态。

**验收：** 静止播放待机、移动脚步与速度基本匹配、攻击/死亡有对应动作；不同模型血条位置与大小合理；模型与血条同生同灭；移动相机、近距离绕行和敌人复用无孤立或重复血条。

### 修复项 7：复用单机立体掉落、拾取与消耗品背包表现（P1）

**要解决：** 道具包没有立体模型，以及联机交互仍是临时文字界面。

**措施：**

- 从单机程序化道具构造中提取共用纯视觉工厂/目录，恢复同样的立体包体、材质、图标和适度浮动。客户端只使用服务器的 DropId、物品、数量、归属、位置和 Revision，不重新随机掉落或挑选落点。
- 复用附近物品列表、F 拾取、名称数量和滚轮选择；滚轮在拾取 UI 接管期间不能触发切枪，并覆盖列表动态增加/合并及单次滚动只选择一次的回归。
- 联机背包复用单机视图，以服务器库存镜像绑定；使用、拆分、移动/交换、整理、丢弃只提交服务器支持的意图。缺少的服务器动作逐项补齐并测试，不调用单机本地库存结算。
- 拾取等待确认期间防止重复提交；两人同时拾取同一件物品只成功一次。失败保留可重试 UI，并按新版本刷新。

**验收：** 两端看到相同可拾取包体与数量；拾取成功后世界掉落与库存一致变化；抢拾取、满背包、失效 Revision 不重复发物品；丢弃重新生成服务器掉落。原有单机消耗品背包不退化，不扩展为新动态背包需求。

### 修复项 8：复用单机升级卡片与进度 HUD（P1）

**要解决：** 联机升级页面与单机肉鸽不一致，及确认/显示状态可能冲突。

**措施：**

- 使用 UpgradeChoiceView 的布局、图标、稀有度、完整中文说明及等级显示。
- 候选 ID、当前叠层、待选次数、等级经验全部来自服务器快照；在客户端建立只读适配，不本地抽卡，也不本地重复应用升级属性。
- 选择提交 ChoiceGeneration 和唯一请求标识；等待确认暂时禁用重复操作。已处理确认不等于接受成功；只有接受后才关闭或进入下一轮，拒绝时刷新当前有效候选并可重试。不要每帧重新 Show 卡片并重置防重状态。
- 输入和鼠标由统一 UI 门控管理。一个玩家选卡或开背包不能暂停服务端，也不能让另一玩家或世界更新停下；关闭后正确恢复操作。
- 初始化、恢复与重入立即从完整快照刷新等级经验，不能等下一次击杀才刷新。

**验收：** 卡片视觉与单机一致、无乱码；显示候选/等级与服务器一致；连续升级和重复点击不多选或多加属性；一人选卡另一人继续正常战斗；双方只见各自应有的候选与库存。

### 修复项 9：完整玩法一致性验收与受控发布（发布门槛）

1. 按正式配置完成 CityNew 全流程：角色准备、各波次与敌人职责、伤害/护甲、经验与卡片、掉落/背包、终端、撤离和结算。逐项对照单机已验收功能，未接入项明确补齐，不能只打一只 Spider。
2. 分层验证：逻辑测试 → 正式 Addressables 资源的加载/复用与 UI 测试 → 图形客户端真实画面 → 公网双客户端同场完整通关。
3. 覆盖单人开房测试与两人同场，静止玩家、移动目标、首次两只击杀后的补生成、后续波次、对象复用、网络短暂停顿、退出/重入和失败返回。
4. 无头或纯逻辑测试不能证明网格可见、动画正确、卡片一致；正式资源与真实画面必须单独过关。自动验收不能关闭敌人行为或增大伤害以绕过用户路径。
5. 每场保留按 MatchId 对齐的简要结果、关键指标、截图/视频和失败原因；在后台、静音完成检查，不抢用户前台窗口。
6. 发布前核对客户端、服务端的协议与内容版本；必要变更明确兼容性，不把“服务端升级”表述成“旧客户端界面会自动升级”。保持登录/房间接口兼容并回归。
7. 使用可回退的服务器发布目录和配置，数据库不为本轮表现修复而重建。保存上一套兼容客户端/服务端包；任一 P0 未通过，不发布为已修复版本。
