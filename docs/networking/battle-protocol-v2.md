# 战斗协议第二版：输入时序与发布约束

## 同步版本

战斗 UDP 载荷版本为 `2`。Unity 的集中定义是
`CoopWireProtocol.NetworkConfigVersion` / `CompatibilityId`；服务器管理脚本的
集中定义是 `issue101_server_manager.BATTLE_PROTOCOL_VERSION`。
房间服务采用该脚本常量作为缺省版本。客户端 Resources 配置和构建清单必须匹配。

此次变化包含：玩家真实已执行输入 Tick、射击显示 Tick 与显式方向、敌人真实快照
Tick 和战局代次、拒绝开火的原因及权威弹药、弹药快照实际覆盖的输入确认序号。不能让第一版客户端按第二版布局解码。
NGO 的 `NetworkConfig.ProtocolVersion` 与分配接口的 `protocolVersion` 均已升级。
账号与房间 REST 路由、数据库、账号和房间数据结构未因此变化。

发布必须一起更新客户端、Linux Dedicated Server 和分配脚本；现有服务器启动参数或
环境配置中如显式指定 `--protocol-version 1`，需改成 `2`。不要仅修改版本字符串来
伪装旧构建兼容。旧下载包应在加入战斗前收到明确版本不兼容提示。

## 连续输入

输入执行时间采用最近收到的服务器 Tick 加本地单调经过时间，不等待每条输入回包。
RTT 的一半只是展现时钟的近似补偿，不作为输入时间的精确单程延迟。
一帧最多发四条输入；没有新快照超过两秒时停止继续预测并等待恢复。
未确认预测历史最多保留两秒输入，且硬上限为 512 条。

新战局、超过半秒的观测中断或超过 0.2 秒的大幅时钟相位偏移会建立新时间原点，
重置延迟估计，清除旧预测及过时的开火、跳跃脉冲，然后从权威状态恢复。
同一原点内估计 Tick 与展现 Tick 保持单调。重复或倒退快照不能延长连接健康期限。
同一战局即使更换时钟原点，已发送的输入 Tick 仍保持单调，等待新的可用 Tick 而非
重用旧时间戳；只有真正增加战局代次时才能重新从低 Tick 开始。

服务器按玩家公平取输入：每人队列上限 32 条，每服务器 Tick 最多处理四条，不把
开火或跳跃静默合并掉。移动积分与预测回放使用相同的有界 Tick 间隔，不能把数秒
停顿一次积分成一次位移。输入序号确认不等于移动已执行，回放起点取真正的
`LastAcceptedClientTick`。

略早到达的未来输入在队列中等待可执行的服务器 Tick，最多暂存超出既有未来许可
四个 Tick 的输入；更远的未来输入立即显式拒绝。等待中的同玩家后续输入不能越序，
也不能阻塞其他玩家。此策略不扩大 Domain 的未来合法窗口。

## 射击反馈与验收边界

接受或拒绝的开火都返回原始输入序号、原因和权威弹药；拒绝开火不能播放命中特效。
晚到反馈不能回滚更晚的弹药快照。射击回溯使用玩家看到的显示 Tick，而移动执行使用
输入 Tick，二者分离。

射击反馈采用独立的小包快速下行：服务器单次计算后发送 UDP 非可靠 RPC，并在之后
两个间隔各补发一次；总共最多三份，队列有界。原可靠射击日志仍保留，用于副本全部
丢失时补漏。输入仍采用同一有序可靠 UDP 通道，未将移动/开火拆成可互相越序的通道。
快速通道不能提前推进可靠日志的读取游标；两条路径共同按事件身份去重，乱序反馈不
能吞掉前一枪，迟到的旧弹药不能覆盖更晚状态，也不能覆盖同 Tick 完整快照的最终状态。
弹药反馈额外携带该快照真实覆盖的输入确认序号，HUD 只对它之后尚未结算的预测开火
扣弹。该序号不能当作移动确认；批处理反馈或提前拒绝也不能通过本枪序号猜测确认前缀。

本地移动预测与未确认输入重放使用服务器相同的场景胶囊碰撞、墙面滑动规则。默认
纯 Domain 测试仍可不注入场景解算器；正式联机接入不可缺少它，否则客户端会先穿墙，
再反复被服务器纠正，甚至将正常贴墙输入误报为不可能位移。
对账后完整权威重放状态用于下一次预测与发送；画面平滑偏移单独存放、有界衰减，
不得把仅平滑一半的显示位置重新作为计算位置，否则短暂缺输入可能导致连续位移拒绝。

域单元测试验证时钟、积压、回放和公平性；PlayMode 验证载荷、拒绝反馈与跨模块接入。
这些测试不能代替同版本双客户端真实公网对局通关：仍需在同一个 MatchId / 连接代次
对齐持续输入、服务器处理、快照应用和画面，并确认世界根、敌人模型与命中体一致。
