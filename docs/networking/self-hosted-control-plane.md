# 自建账号与房间控制面

## 目标与边界

联机客户端只连接项目自有的 HTTPS 控制面和 Unity Linux Dedicated Server，不再把 Unity Authentication、Multiplayer Sessions、Lobby、Relay 或 Matchmaker 作为运行前提。Unity Netcode for GameObjects 与 Unity Transport 仍是客户端和自有 Dedicated Server 间的通信库，不是第三方转发服务。

账号与房间服务、战局分配器和游戏进程可以部署在同一台机器，也可以以后分别迁移；客户端只认稳定的 HTTPS API 契约和战局分配结果，不认服务器上的绝对路径或某个云厂商。当前小规模演示只承诺单台机器的一场活动战局，不据此推断可承载并发房间数。

## 请求链路

1. 客户端通过 HTTPS 注册、登录并取得有期限的身份令牌；房间列表、创建、加入、选角、准备和退出都由自建服务鉴权并处理。
2. 房主开局时，服务端以数据库内的成员和准备状态为准，调用本机战局管理器启动 Dedicated Server，生成加载轮次和短期入局票据。客户端提交的玩家名单只用于一致性检查，不能决定真实成员。
3. 两名客户端分别取得只属于自己账号的入局票据，直接经 UDP 连接同一游戏进程；游戏服务器验证票据、版本和玩家席位后，权威处理输入、移动、射击、敌人、波次、掉落和结算，并向客户端复制状态。
4. 客户端可预测自己的操作和播放表现，但不能自行确认伤害、掉落或任务完成。

控制面 API 是账号、房间和战局分配服务；它**不转发游戏 Tick 数据**。校园网若阻断自定义 UDP 端口，账号/房间仍可能正常，但战斗连接需单独排查或将来增加受控回退链路。

## 数据持久化与安全

- 账号 ID 与密码哈希、令牌摘要、房间记录保存在可配置路径的 SQLite 数据库中，默认位于 `/srv/fps/data`，不位于 `/srv/fps/current` 或版本发布目录。数据库使用版本化 schema 和事务，密码、原始令牌不得进入日志与仓库。
- 游戏进程状态文件、进程号和诊断属于运行态；数据库备份不能让一场正在进行的战斗在另一台机器上无缝续跑。迁移应先停止接收新房间、完成或结束当前战局，再切换主机。
- 客户端内置默认 HTTPS 地址；`Application.persistentDataPath/CoopDedicatedServerSettings.json` 可覆盖地址与证书指纹。优先为正式部署使用稳定域名和可信 CA 证书，通过 DNS 调整主机；自签证书轮换时必须同步客户端 pin 配置。绝不自动回退到 HTTP。
- 客户端只缓存短期访问令牌，不保存密码；macOS/Linux 将缓存目录限制为 `0700`、令牌文件限制为 `0600`，权限设置失败则不写持久缓存。该本地缓存仍不能抵御同一系统账号下的恶意程序；正式运营需接入平台安全凭据存储和完整账号恢复机制。
- 当前 Unity 托管账号密码无法读取或离线迁移，新自建账号需要重新注册。旧 Unity 项目数据保持原状，不作为自动迁移来源。

## 迁移另一台服务器

1. 保留旧机器与发布版本，不先删除旧数据库、证书、密钥或备份。
2. 可先用 SQLite 在线备份做预热副本；正式切换前必须停止旧控制面写入，等待当前战局结束并停止旧控制面服务，再生成**最终备份**并执行完整性校验。将最终备份安全传到新机器的持久数据目录，恢复后再次校验账号数、房间数与 schema 版本。不要在数据库以 WAL 模式运行时只复制单个 `.sqlite3` 文件，也不要在最终备份之后继续向旧库写入。
3. 将运行所需密钥通过安全通道或 Secret Manager 注入新机器；不要打印或提交密钥。票据签名密钥如轮换，尚未过期的旧战局票据会失效，应在战局结束后切换。
4. 部署相同协议与内容版本的 Linux Dedicated Server、账号/房间服务和战局管理器；通过配置文件设置公开 HTTPS 地址、UDP 地址、端口、数据库路径与证书。先在新机器验证健康检查、注册/登录、房间和单房战斗。
5. 稳定域名可调整 DNS 指向新机器；若使用 IP 或证书 pin，先下发客户端外部配置或发布新包，再切换。验证双客户端入局、断线重连与结算后保留旧主机及最终备份作为回滚点；回滚时也须停止新主机写入并迁回新增数据，不能简单启动旧库覆盖新账号。

## 验收门槛

- 无境外代理的两台客户端可通过自建 API 注册/登录，能够看到同一房间成员、角色、准备与开局状态；客户端运行时无 Unity Authentication/Lobby 请求。
- 房主一人和双人两种情形均可开局；未准备的成员、非房主或房间外账号不能分配战局或领取他人的票据。
- Dedicated Server 与两个客户端进程看到同一三波 CityNew 权威战局，能够断线重连并完成终端与撤离；错误版本和无效票据被拒绝。
- 数据库在线备份后可在另一路径恢复，账号能重新登录；失败的迁移可以切回旧机器且旧库仍在。

上述验收项是发布门槛，不因为代码编译或单机测试通过就自动视作完成。
