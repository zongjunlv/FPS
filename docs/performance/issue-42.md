# Issue 42：按距离和战斗重要性实现 AI LOD

## 设计

- 近距离：决策最多间隔 2 帧；新晋级目标的视线检查在 1–2 帧内执行。
- 中距离或处于可疑、警戒、搜索状态：决策最多间隔 6 帧，视线目标间隔 8 帧。
- 远距离巡逻：决策最多间隔 20 帧，视线目标间隔 24 帧，并暂停 NavMeshAgent；晋级后恢复原目的地。
- 常规视线检查继续受每帧预算保护；极端情况下以轮询上限代替一次性执行全部 Raycast，避免近层拥挤造成帧尖峰。
- 受击立即晋级近距离；枪声、小队警报和新视觉情报请求即时评估。
- 所有降频逻辑使用累计时间，死亡、伤害、池回收等同步事件不受 LOD 影响。

## 固定验证条件

沿用 Issue 30：100 敌人、1920×1080 Windowed、PC 画质、种子 30030、每轮预热 5 秒并采样 20 秒。使用同一 Development Player 分别关闭和开启 LOD，各运行 3 轮并取中位数。

为抵消 MacBook Air 无风扇机型的连续温升偏差，采集顺序固定为：关闭→开启→开启→关闭→关闭→开启。

## 实测结果

| 指标 | 关闭 LOD | 开启 LOD | 变化 |
| --- | ---: | ---: | ---: |
| 平均 FPS | 69.93 | 95.30 | +36.27% |
| 平均帧时间 | 14.39 ms | 10.51 ms | -26.93% |
| P95 帧时间 | 48.30 ms | 29.49 ms | -38.95% |
| 主线程平均耗时 | 14.29 ms | 10.48 ms | -26.65% |
| 主线程 P95 | 48.27 ms | 29.40 ms | -39.10% |
| AI 决策执行量 | 280,941 | 227,153 | -19.15% |
| 采样期创建 | 0 | 0 | 持平 |

常规视线检查继续受每帧 4 次预算约束，因此百敌全部进入近层的极端拥挤状态下，全体最大轮询延迟由 25 帧变为约 30 帧；受击、警报和 LOD 晋级使用独立紧急通道，不等待常规轮询。该取舍避免了 100 个近敌在同一帧集中 Raycast 引发的帧尖峰。
