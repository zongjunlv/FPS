# Issue 43：移动敌人空间索引

## 设计

- `EnemySpatialHash` 隐藏网格划分、桶迁移、精确半径过滤和复用桶管理。
- `EnemySpatialIndexService` 负责 Unity 对象注册、移动同步、回收注销、标签和存活过滤。
- 支援能力继续依赖 `IEnemyNeighborQuery`；小队警报先通过空间半径查询裁剪接收者，再执行原有情报和 NavMesh 逻辑。
- 对象池在 `PrepareForPool()` 当下注销，不等待延迟禁用。
- 正式查询可切换为朴素参考实现；两条路径共享 Controller/Health 缓存，只对比候选枚举方式。
- 空间查询对相邻旧网格保留一帧安全边界，并以精确距离二次过滤，避免 NavMeshAgent 同帧跨格漏检。
- 有最大数量限制时按注册顺序稳定截断，保证与朴素参考结果一致；不限量生产查询不承担无意义排序成本。

## 验证条件

100敌人、1920×1080 Windowed、PC画质、种子30030、AI LOD开启。每轮预热5秒并采样20秒，朴素扫描与空间哈希各4轮，按关→开→开→关→关→开→开→关的ABBA对称顺序采样，轮次间冷却10秒。

## 执行

```bash
./scripts/performance/run-issue43-spatial-comparison.sh
```

结果写入 `artifacts/performance/issue43/`，正式中位数汇总会同步保存在仓库文档目录。

## 实测结果

| 指标 | 朴素扫描 | 空间哈希 | 变化 |
| --- | ---: | ---: | ---: |
| 平均 FPS | 100.44 | 92.00 | -8.40% |
| 平均帧时间 | 10.07 ms | 11.05 ms | +9.79% |
| P95 帧时间 | 21.45 ms | 27.95 ms | +30.32% |
| 主线程平均耗时 | 10.04 ms | 11.03 ms | +9.89% |
| 邻居查询总耗时 | 111.06 ms | 102.64 ms | -7.58% |
| 单次邻居查询平均耗时 | 64.02 μs | 64.08 μs | +0.09% |
| 平均 GC/帧 | 9,190.75 B | 9,714.91 B | +5.70% |
| 采样期创建 | 0 | 0 | 持平 |

压力场景中敌人最终高度聚集，空间索引平均每次访问约99.7个候选，而朴素扫描为100个，单次查询耗时因此基本持平（+0.09%）。这组结果如实说明：当前密集阵型没有空间裁剪收益；索引价值主要面向后续更大地图、更分散敌群的扩展场景。

本轮首尾帧率存在显著热衰减，整机 FPS、帧时间和主线程数据只保留为原始记录，不将其归因为空间索引。可复现验收依据为：同缓存公平对照、21项关键回归、固定样本结果一致、稳定查询零托管分配，以及上述100敌人查询耗时记录。
