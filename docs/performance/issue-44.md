# Issue 44：Job/Burst 批量视线感知

## 实现设计

- 主线程只收集本帧预算内的敌人，并提交一批视线描述；目标距离与视野角预判由 Burst Job 并行执行。
- 物理遮挡通过 `RaycastCommand.ScheduleBatch` 异步批量查询，下一帧统一归并结果，避免逐敌同步射线阻塞主线程。
- 自身与目标碰撞体在启用、换目标和对象池复用时缓存为 `EntityId`，Job 内无需访问托管组件。
- `NativeList` 与托管请求缓冲由调度器持有并复用，停用或销毁时先完成未决 Job 再释放。
- 每个请求携带对象池代际和提交时的目标位置；死亡、停用、回收或复用后的旧结果会被拒绝，也不会隔墙读取玩家最新位置。
- 调度比同步路径提前一帧，近距离敌人的检查间隔仍不超过 2 帧，异步结果延迟不超过 1 帧。

## 100 敌人 A/B 条件

使用同一 Development Player、100 敌人、1920×1080 Windowed、PC 画质、固定种子 30030、AI LOD 与空间索引开启、每帧视线预算 32。同步射线与 Job/Burst 各运行 4 轮，采用 ABBA 对称顺序并在轮次间冷却。

```bash
./scripts/performance/run-issue44-sight-comparison.sh
```

原始报告、日志和汇总写入 `artifacts/performance/issue44`。仓库只保留最终中位数汇总。

Job/Burst 方案中位数每轮完成约 2,894 个批次、101,788 条命令；未出现陈旧结果被错误应用，批处理器热路径专项测试为零托管分配。

首尾运行之间存在明显设备热衰减（最大/最小 FPS 比为 1.55），因此整帧提升只作为参考，不夸大为稳定硬件收益。验收重点是同等工作量、延迟边界、生命周期安全以及批处理热路径零分配。
