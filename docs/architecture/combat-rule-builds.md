# 战斗触发器与标签构筑

Issue 59 在数值型 `GameplayEffect` 之上增加数据驱动规则层。卡牌或构筑只声明触发条件和效果链，输入、武器与玩家控制器不承载具体卡牌逻辑。

## 处理链路

```text
命中 / 击杀 / 换弹 / 受伤 / 破甲 / 低血量
                    │ 标准上下文（Tick、实体、标签、数值）
                    ▼
              CombatRuleEngine
            条件 → 冷却 → 概率
                    │ 有序效果执行计划
          ┌─────────┼──────────┐
          ▼         ▼          ▼
       状态效果   邻近扩散    HUD 提示
```

- `CombatBuildDefinition` 聚合可安装的规则集合。
- `CombatRuleDefinition` 声明触发器、来源/目标标签、生命比例条件、固定 Tick 冷却和万分比概率。
- `CombatRuleEffectDefinition` 声明目标、状态效果、范围、目标上限与后续效果。
- `CombatRuleEngine.Process(context)` 是纯规则决策缝隙；场景适配器只执行返回的计划。
- 概率由战局 Seed、事件 ID 与规则 ID 计算，不依赖 Unity 随机数或帧率。

## 首个完整联动

`build.ember_chain` 默认安装两条规则：

1. 玩家命中存活敌人时施加 `status.burn`。
2. 击杀带 `status.burning` 标签的敌人时，在 7 米内最多选择 4 个存活敌人扩散燃烧，并显示“余烬扩散 ×数量”。

邻近目标由敌人空间索引查询；测试或无索引环境使用按实例 ID 排序的确定性回退查询。燃烧视觉和头顶状态复用原有持续效果表现。

## 安全与一致性

- 最近 256 个事件 ID 用于去重，防止同一次命中或击杀重复结算。
- 后续效果最大深度为 16，并通过访问集合阻止循环依赖无限递归。
- 敌人死亡时保留死亡前燃烧标签；只有对象池重置才清除，避免回收顺序污染判定或下一代敌人。
- 存档追加可选的构筑块，保存已安装构筑、规则冷却、事件去重窗口和事件序号；旧 schema-v2 存档校验和保持兼容。
- 回放校验状态包含相同构筑字段，触发次数、冷却和去重差异会形成明确的校验偏差。
- 内容校验会阻止非法标签、缺失状态效果、后续效果循环、不兼容目标和重复稳定 ID 进入正式内容。
